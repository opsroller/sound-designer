# Sound provenance

Every sound that ships must be one the project may ship, and anyone must
be able to see where it came from. This skill applies the
`engineering-practices` `provenance` skill to audio; that skill's
decision table and log format win where they differ.

## Origins and what to record

| Origin | Allowed | Record in the provenance log |
|---|---|---|
| Generated by your script or synth patch | Yes; commit the script/patch (outside the build) | "generated by <script/patch path>", date |
| Your own recording | Yes | Recordist, date, place, what was recorded, session notes path |
| Your own composition | Yes | Composer, session/project path |
| Layered or processed from the above | Yes | Each source layer's origin |
| Licensed library or marketplace pack | Only if the licence covers this use (product type, platforms, distribution, modification) | Library name, vendor, licence name and URL or file, purchase/account owner, files used |
| Creative Commons, CC0 | Yes | URL, author, CC0 |
| Creative Commons, CC BY | Yes, if attribution is given as required | URL, author, licence version, changes made; add to credits |
| CC BY-SA | Only if the project's licence policy allows share-alike for assets | As CC BY, plus share-alike note |
| CC BY-NC, CC BY-ND, "free for personal use", unknown, no licence | **Never** for a project that may be sold or relicensed | Leave it out |
| Synth presets and sample-based instruments | Usually yes for music output; check the instrument's EULA for standalone sample use | Instrument/product and EULA note when samples are exposed |
| AI-generated audio | Only as the profile allows, checked for imitation of specific works or voices | Tool category, prompt summary, date |

Rules:
- Check the licence on each individual file's page; on community sites
  each contributor chooses a licence, so one pack can mix terms.
- Read the licence text, not a summary.
- "Royalty-free" is not "licence-free": read what it permits.
- Never imitate a recognisable sound, theme, melody or a real person's
  voice, from any medium, even when resynthesised.
- Keep licence files or receipts where the profile says (often a
  `licenses/` folder) so audits do not depend on a website staying up.

## Steps

1. Before importing: classify with the table. Unsure? Leave it out and
   ask the project-manager.
2. On import: write the provenance line. When several people work in
   parallel, each returns lines; one person applies them in one edit.
3. Credits: add every attribution a licence requires to the credits file.
4. Before release: audit. Every shipped audio file must match a log
   line; every log line must match a file (remove stale ones).

## Audit checklist

- [ ] Every shipped audio file has a log entry with origin and licence.
- [ ] No non-commercial, no-derivatives, personal-use or unknown items.
- [ ] Generator scripts, patches and sessions are committed for every
  "generated" or "own work" entry.
- [ ] Credits include every required attribution.
- [ ] Placeholders are either replaced or themselves cleared.

## Failure modes

- A placeholder from an unclear source survives to release.
- Attribution recorded in the log but missing from shipped credits.
- One CC BY-NC file inside an otherwise CC0 pack.
- "It's only 2 seconds": length does not change copyright.

## Documentation

The provenance log and credits are **reference**; update them in the
same change as the sound. A project-wide licence policy decision belongs
to an **explanation** written with the project-manager.
